# 大規模災害時の大阪再構築（cold DR）

**目標**：被災から14日以内に復旧。困難な場合は5日以内に復旧スケジュールを提出（提案書 項番15）。

| # | 作業 | 担当 | 目安 |
|---|---|---|---|
| 1 | 被災判定、DR 発動承認 | 情報館様・PM | 0日 |
| 2 | `environments/prod-osaka-rebuild` の tfvars を確定 | 基盤 | 1日 |
| 3 | 3-network（大阪）適用 | 基盤 | 1日 |
| 4 | 4-data 適用、Cloud SQL を大阪保管のバックアップから復元 | 基盤・DB | 2〜4日 |
| 5 | Spanner：エクスポートからインポート、または Cloud SQL/GCS から再生成（訓練で速い方を採用） | DB | 2〜5日 |
| 6 | 原本：大阪 WORM バケットから新バケットへコピー | 基盤 | 並行 |
| 7 | 5-app-infra 適用（同一 digest のイメージを大阪 Registry へコピー） | 基盤・アプリ | 1日 |
| 8 | 更新データの再投入（バッチ）、整合確認 | アプリ | 1〜2日 |
| 9 | DNS を新 LB IP へ切替、Sorry 解除 | 基盤 | 0.5日 |
